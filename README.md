# ReBook

## 이름을 선택한 이유

중고책을 무조건 버리지 말고, 다시 판매해서 재사용할 수 있도록 돕는다는 의미를 담고자 선택했습니다.

## 프로젝트 목적

이 프로젝트는 중고책을 판매하려는 사용자가 오프라인과 온라인 판매 방식을 비교하고, 매입 가능 여부와 예상 가격을 확인하거나 온라인 판매를 진행할 수 있도록 돕는 서비스입니다.

## 주요 사용자

- 중고책을 빠르게 정리하고 싶은 사용자
- 중고책 판매 가능 여부와 예상 가격을 알고 싶은 사용자
- 중고책 가격을 직접 정해서 온라인으로 팔고 싶은 사용자
- 외부 판매 채널을 통해 중고책을 판매하고 싶은 사용자

## 핵심 기능

### 1. 질문 기반으로 한 매입 가능 여부 및 예상가 확인

사용자가 책 상태에 대한 질문에 답변하면 매입 가능 여부, 매입불가 사유, 상태 등급, 등급 판정 사유, 예상 매입가를 확인할 수 있다.

### 2. 바코드 기반 빠른 매입 가능 여부 및 예상가 확인

질문을 건너뛰고 빠르게 확인하고 싶은 사용자는 ISBN 바코드를 스캔하여 외부 매입 조회 페이지에서 빠르게 매입 가능 여부와 가격을 확인할 수 있다.

### 3. 온라인 판매글 등록

사용자가 직접 중고책 가격을 정하고, 책 상태와 설명을 작성하면 온라인 판매글을 등록할 수 있다.
추후에는 AI가 판매글 제목과 설명 초안을 자동으로 생성하여 사용자가 더 쉽게 판매글을 작성할 수 있도록 돕는다.

### 4. 외부 판매 채널 연결

사용자는 알라딘, YES24, 중고거래 플랫폼 등 외부 판매 채널을 통해 중고책을 판매할 수 있도록 연결받을 수 있다.

## 1차 MVP 범위

1차 MVP는 자바 콘솔 프로그램으로 구현한다. 추후 웹과 앱으로 확장할 수 있다.

### 포함할 기능

- 책 제목 입력
- 책 상태 질문 출력
- 책 상태에 대한 사용자 답변 입력
- 매입불가 사유 판단
- 매입 가능 여부 출력

### 제외할 기능

- 상태 등급 책정
- 등급별 매입가 계산
- 바코드 스캔
- 온라인 판매글 등록
- AI 판매글 생성
- 외부 판매 채널 연결
- 데이터베이스
- 웹 화면
- 로그인
- 배포

## 개발 단계 설계 메모

> 객체지향 구조로 리팩터링과 저장소 구조 분리는 따로 진행한다.  
> 객체지향 리팩터링은 코드의 책임을 나누는 훈련이고, 저장소 구조 분리는 데이터 저장 책임을 분리하는 훈련이다.

> 바코드 기반 빠른 확인 기능은 카메라 접근과 웹/앱 화면이 필요하므로 웹 화면 연결 이후에 구현한다.

> 예외 처리는 별도 기능으로 분리하지 않고, 각 단계에서 필요한 입력 검증과 오류 처리를 함께 구현한다. Spring Boot 전환 이후에는 공통 예외 처리 구조로 확장한다.
